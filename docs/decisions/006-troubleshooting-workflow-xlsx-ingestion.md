# 006: 排障流程 XLSX 的通用导入规则

日期：2026-08-05

## 背景

命令小词典使用“命令 / 命令视图 / 说明”等列。实际运维知识还常以编号流程记录：某个现象先检查什么、结果异常时进入哪一步，以及最后的升级建议。这类工作表不应因为没有命令词典表头而被静默忽略。

## 决策

在现有 XLSX 导入器中增加一个通用的流程表适配器，且只在该工作表没有识别出命令词典单元时启用。

当工作表既不是命令词典，也不满足编号排障流程格式时，导入器会按“每行一条知识参考”保存非空单元格内容，并保留工作表、区段和行号。文本中明确出现的 `show`、`display`、`ping`、`tracert` 或 `traceroute` 命令会作为候选命令提取；没有完整命令的行仍作为参考知识进入索引，不会被静默丢弃。

- 一个流程表至少要有两条“编号步骤 + 说明”，其中至少一条带 `show`、`display`、`ping`、`tracert` 或 `traceroute` 的诊断命令。
- 每条步骤都保存为独立、可检索的知识单元，保留工作表、流程区段和原始行号。
- 适配器只读取步骤号、说明和诊断命令；不读取后续参考配置列，从而避免把真实业务配置、设备日志或配置片段加入本地索引。
- 诊断命令中的 IP 及常见的 VPWS/隧道运行参数会转为占位符，例如 `<对端IP>`、`<VCID>`、`<隧道ID>`。只要发生参数脱敏，该知识会携带 `requiresParameters` 标记。
- 流程表的配置参考列会作为“配置核对模板”导入：保留 `VPWS`、接入接口、对端、`VCID`、封装、标签、VLAN 动作和隧道等字段结构，但业务名、地址、接口、标签、路径编号和模板名称都会脱敏为占位符。
- 带 `requiresParameters` 的流程命令默认只可作为排障提示和候选模板。VPWS Ping 是受限例外：用户明确点名业务、锁定终端的现有回显中唯一找到该业务的 L2VC 参数、且补全后的命令仍匹配同一条可靠模板时，Agent 可以自动执行；不得猜测业务、参数或对端地址。
- 配置核对模板仅用于解释和两端比对，永远不是可由 Agent 下发的配置命令。
- 当检索命中任一流程步骤时，检索结果会补齐同一文档、工作表和流程区段内的全部步骤，并按步骤号返回。
- 用户明确说明“未接设备、只要步骤、不执行命令”时，Ask 和 Agent 都直接渲染这些有来源的流程步骤，不请求模型补全，也不生成知识库之外的厂商命令。
- 已在旧版本导入过同一份工作簿时，用户再次导入该文件会显式刷新为当前解析版本，不会因文件哈希相同而保留旧的缺失字段索引。
- 本次通用参考表适配升级了解析器版本；旧版本索引再次导入时会自动刷新，不需要修改源代码或手工删除知识库文件。

## 结果

以后可在同一个 Excel 中新增排障 Sheet，而不需要为每一张表编写代码。表格中的说明负责定义“现象到下一步”的业务知识；命令词典继续提供固定、已验证的只读命令和 CLI 视图约束。Ask 始终只解释和给候选；Agent 默认只自动执行无参数模板、证据可靠、适用 CLI 匹配的只读命令，受限 VPWS Ping 例外须满足本决策列出的现有回显参数解析条件。
