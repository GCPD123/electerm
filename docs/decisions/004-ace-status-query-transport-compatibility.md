# ADR-004：MVP ACE 状态查询兼容已连接的 Telnet 会话

- 状态：已决定
- 日期：2026-08-04

## 背景

真机验证发现，FiberHome SPN 的 ACE 用户视图可通过已有 Telnet 会话进入，提示符可为 `ACE#`。此前的终端上下文模块仅把 SSH 视为可自动执行的连接，并且没有识别该提示符，导致已有可靠知识依据的 `show ospf neighbor` 状态查询被错误阻止。

## 决策

- 对已经由用户建立的单一终端会话，`ssh` 和 `telnet` 都可作为“已连接”的传输类型；这不是让 Agent 创建 Telnet 连接，也不规定任何设备登录或进入步骤。
- `ACE#` 是已兼容的一种提示符，不是设备名称或型号规则。对于终端历史中存在 FiberHome 登录标识的会话，通用的 `设备名称#` 也识别为 FiberHome 用户视图；不得从主机名、IP、标签标题或设备型号猜测 CLI。
- MVP 中的 FiberHome 状态查询可自动执行，前提仍为：可靠 RAG 证据、固定目标、已识别的 FiberHome CLI、终端就绪、非分页、非密码等待，以及命令属于非敏感状态查询。
- 对带参数的 VPWS Ping 知识模板，只有用户明确点名业务、锁定终端的现有回显中唯一找到该业务的 L2VC 参数、且补全后的命令仍匹配同一条可靠知识模板时，才可自动执行；不得猜测业务、参数或对端地址。
- `show running-config`、配置显示、密码/密钥相关读取仍属于敏感读取，不能因 `show` 或 `display` 前缀自动执行。

## 后果

用户已连接到 FiberHome Telnet 或 SSH 会话后，常见的已收录状态查询（例如 OSPF 邻居查看）不再因传输方式或设备名称不同被误拦截。终端重新检查会保留足够的近期历史，以识别已出现的 FiberHome 登录标识。Ask 的只检索边界、目标锁定、分页/密码等待拦截和敏感读取拦截保持不变。
