# ADR-003：以 FiberHome RAG 作为首要产品能力

- 状态：已决定
- 日期：2026-08-02

## 背景

Electerm 已经提供成熟的终端、SSH、SFTP、书签、会话和 AI Ask/Agent 能力。FiberTerm 当前最有辨识度、也最适合作为项目成果展示的能力，不是重做这些通用功能，而是让终端能够依据 FiberHome 命令手册、技术文档和案例回答问题、生成有来源的设备命令，并进入受控执行流程。

## 决策

FiberTerm 的当前产品范围收敛为：

> Electerm 稳定底座 + FiberHome 展示品牌 + 本地优先的 FiberHome RAG。

RAG 模块成为下一阶段最高优先级。广泛的资产管理、批量运维、完整 RBAC、CMDB 和无人值守自动化暂缓。

第一条体验路径为：

```text
用户问题
→ 识别当前设备上下文
→ 检索 FiberHome 知识库
→ 返回带来源的解释与候选命令
→ Ask 停止在 AI 输出窗口，不主动执行
→ 用户自行复制/操作，或显式点击既有运行按钮
```

Ask 与 Agent 的原有语义保持不变：Ask 是建议模式，不调用工具、不主动向终端写入；Agent 才是可调用终端工具的执行模式。RAG 只增强两者使用的知识依据，不改变模式权限。

## 边界

- RAG 提供知识证据，不提供执行授权。
- Ask 中的运行图标属于用户主动触发，不得被 RAG 自动点击、绕过或改造成自动执行。
- 无可靠证据、设备型号或软件版本不匹配时，应澄清或拒绝猜测命令。
- 文档默认保存在本地；使用云端 embedding 前必须说明哪些内容会被发送给第三方。
- 首版只服务少量真实 FiberHome 文档和单设备交互，不建设大而全的知识平台。
- 品牌改动继续保持展示层边界，不更改内部应用 ID、数据目录或升级协议。

## 后果

### 正面

- 最大程度复用 Electerm，减少开发面和回归风险。
- 可以用少量真实手册迅速形成可演示的差异化闭环。
- 知识模块通过窄接口接入 Ask/Agent，便于后续跟随 Electerm 上游更新。

### 代价

- 文档质量、型号与版本元数据会直接决定答案质量。
- 聊天模型和 embedding 模型可能来自不同供应商，需要独立配置。
- 命令可执行并不等于命令安全，最低限度的确认与执行边界仍不可省略。
