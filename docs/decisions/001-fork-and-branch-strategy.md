# ADR-001：Fork 与分支策略

- 状态：已接受
- 日期：2026-08-02

## 背景

FiberTerm 需要长期基于 Electerm 开发，同时保留官方升级能力、稳定参照和按功能审查的能力。直接在 Fork 的 `master` 上连续修改会把官方跟踪、产品集成和未完成实验混在一起。

## 决策

- 保留 `origin`（个人 Fork）和 `upstream`（官方仓库）两个远程。
- `codex/smartterm-base` 固定可复现的官方基线。
- `codex/smartterm-main` 作为 FiberTerm 产品集成主线。
- 一个明确功能对应一个 Codex 会话和一个 `codex/` 分支，默认从产品主线创建。
- 功能通过测试和用户验收后再合并；未完成的品牌、研究和功能分支彼此隔离。
- 向 Electerm 官方贡献时，从干净官方代码线建立仅含通用修改的分支，不从 FiberTerm 产品分支直接提交 PR。

## 影响

优点是容易比较、回滚、审查和同步上游；代价是需要维护清晰分支状态。路线图必须记录长期分支用途，避免把旧分支误当产品主线。
