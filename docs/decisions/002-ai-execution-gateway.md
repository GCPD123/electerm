# ADR-002：AI 变更型操作必须经过统一执行网关

- 状态：方案已接受，2026-08-02 补充分级授权设计，尚未实现
- 日期：2026-08-02

## 背景

Electerm 已具备内置 Agent、Ask 代码运行、MCP 命令和终端执行能力，但安全校验分散：内置 Agent 和 Ask 可直接执行，MCP 后台命令也可绕过前台校验。只给某一个入口增加确认框不能形成可靠边界。

## 决策

- 建立统一 `Execution Gateway`，作为所有变更型终端/SFTP 操作的唯一入口。
- Agent、Ask、MCP 和未来企业自动化使用相同的动作提议、目标快照、风险判断、审批和结果模型。授权档位只改变策略决策，任何档位都不能绕过网关。
- Ask 保持咨询和解释定位，不允许模型自主调用变更型工具。用户主动运行 Ask 返回的代码时，该动作仍要提交给执行网关。
- Agent 提供三个当前会话级授权档位：
  - **请求批准**：每条终端命令执行前均由用户确认。
  - **替我审批（建议模式）**：独立审查决策仅对明确识别为低风险、只读、单目标的命令自动执行；审查失败、证据不足以及中高风险动作转人工批准。
  - **受控完全执行**：在用户明确授权的当前会话和固定目标内，自动执行策略允许的低/中风险动作；不等于关闭策略或取得整台计算机的无限权限。
- 第一版默认使用“请求批准”。用户可以主动切换到“替我审批”或“受控完全执行”，提升权限时必须清楚展示目标、动作范围、有效期和不可绕过的规则。
- 单项批准区分“仅本次”和“当前会话同类动作”，默认选择最窄范围；不提供跨会话或永久的模糊放行。
- 授权默认只在当前 AI 会话和固定终端目标内有效，不跨应用重启持久化。新建/切换目标、SSH 重连、主机指纹或登录身份变化、进入提权 shell、策略版本变化、编辑命令或扩大范围后，旧授权失效并降级为“请求批准”。
- 终端输出经过命令边界、限长和脱敏后才能回传模型。
- 提示词 guardrail 和正则黑名单只能作为辅助规则，不能替代代码级强制策略。

## 不可覆盖的安全优先级

策略必须按以下顺序判断，后面的授权档位不能覆盖前面的决定：

```text
企业/内置 deny
→ 始终人工确认
→ 作用域检查
→ 当前会话授权档位
→ 执行或拒绝
```

- **永久拒绝**：明确格式化或宽泛递归删除、规避风险识别、篡改执行网关/审计/安全策略、目标或 shell 无法确认、企业策略禁止的动作。
- **始终人工确认**：提权和权限修改、服务重启/停止、网络或路由变更、删除/覆盖、配置恢复、软件/固件升级、批量设备、目标扩大、凭据输入、持久化后台任务，以及高风险或无法可靠分类的动作。
- 用户只能提升授权档位，Agent、模型输出、终端内容和 MCP 客户端都不能自行提升权限。
- 用户可随时降级或撤销；撤销后取消待审批提议并阻止新的终端写入。所有自动批准、人工批准、提升、降级和撤销都必须进入审计事件。

## 影响

现有 Agent 循环、工具 schema、终端适配和会话 UI 可以复用，但所有直接调用终端写入的入口都要逐步收口。权限档位、固定目标、有效期和撤销状态应组成独立 `ApprovalSession`，作为 `ActionProposal` 的策略上下文，而不是散落在各入口的条件判断。MCP 审批可能需要异步请求 ID，避免长时间占用 HTTP/IPC。
