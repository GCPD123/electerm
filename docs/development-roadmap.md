## 建议开发顺序

### 阶段 A：项目治理基础

- 建立 AGENTS、架构、路线图、上游同步和 ADR 文档。
- 固化一个功能一个会话、一个分支、先方案后实施的流程。
- 用户审核后合并文档到 `codex/smartterm-main`。

### 阶段 B：AI 安全执行 P0

- 建立统一的动作提议、策略判断和执行网关。
- 内置 Agent、Ask 代码块、MCP 前台/后台命令全部接入同一入口。
- 未批准时保证终端零写入；严重风险默认拒绝。
- 第一版所有命令都要求用户点击执行，不启用无感自动运行。

### 阶段 C：首个可体验闭环

- 命令卡片展示目的、目标设备、命令、风险和理由。
- 支持批准、编辑、拒绝、取消。
- 采集命令级输出、退出码、超时和等待输入状态，并让 AI 解释结果。

### 阶段 D：企业知识最小闭环

- 先选择少量 FiberHome 官方手册验证切片、检索和引用。
- 把知识回答与终端目标、设备型号和软件版本关联。
- 知识内容不得绕过执行审批。

### 阶段 E：设备能力与审计

- 设备资产/标签、命令适配、配置备份和巡检。
- 追加式执行审计、策略版本和组织控制。
- 在证据充分后再讨论批量或受控自动执行。

## 暂不安排

- 重写 SSH、终端模拟器或 SFTP。
- 高风险无人值守执行。
- 在安全执行网关完成前直接扩展 Agent 自动操作范围。
- 未取得官方资源前发布低清或 AI 重绘的 FiberHome Logo。

## 每个功能的标准流程

```text
明确结果
→ 新建聚焦会话
→ 从 codex/smartterm-main 建功能分支
→ 阅读 AGENTS 与相关文档
→ 方案/边界/测试经确认
→ 小步实施与针对性测试
→ 差异审查和用户验收
→ 清晰提交
→ 合并产品主线
```
