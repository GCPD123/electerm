# FiberTerm 品牌化第一阶段计划

## 目标

在不改变 SSH 核心、用户数据目录、配置格式和更新机制的前提下，将用户可见的产品名称逐步调整为 FiberTerm，并记录正式发布前必须替换的官方品牌资源。

## 阶段

- [x] 阶段 1：创建 `codex/branding-name` 功能分支
- [x] 阶段 2：定位 Electerm 品牌文字、窗口标题和关于页面入口
- [x] 阶段 3：实施最小范围的 FiberTerm 名称与公司归属文字修改
- [x] 阶段 4：运行针对性检查并启动应用验证
- [ ] 阶段 5：整理变更并提交功能分支（进行中；不自动合并产品主线）

## 边界

- 不修改内部应用 ID、配置目录和用户数据路径。
- 不修改 SSH、SFTP、AI 请求或命令执行逻辑。
- 不替换正式公司 Logo；当前只建立占位与待办。
- 未经用户确认，不合并到 `codex/smartterm-main`。

## FiberTerm 强制质量门禁

1. 修改前写清目标、影响范围和明确不改的模块。
2. 每个功能使用独立分支，不混入顺手重构。
3. 优先最小改动，避免全局替换和内部身份变更。
4. 提交前审查全部差异并清理调试代码、临时脚本和纯格式噪声。
5. 至少执行针对性规范检查、回归测试、正式构建和实际运行验收。
6. 核心终端、SSH、配置与用户数据路径必须有专项保护。
7. 测试失败必须区分代码回归与环境限制，未经说明不得忽略。
8. 未通过验收的功能不得合并到 `codex/smartterm-main`。

## 上线前必须完成

- [ ] 获取 FiberHome 官方 SVG Logo，或透明背景高清 PNG。
- [ ] 核对官方品牌标准色、留白和最小尺寸规范。
- [ ] 使用官方原文件替换临时品牌资源，禁止用截图或 AI 重绘稿作为正式 Logo。

## 错误记录

| 错误 | 次数 | 处理 |
|---|---:|---|
| 初次组合式品牌搜索未命中 | 1 | 改用精确字符串和配置文件搜索 |
| PowerShell 禁止执行 `npm.ps1` | 1 | 改用 `npm.cmd` 或直接调用 Node 入口 |
| Windows 下项目 lint 脚本使用 Unix 路径 | 1 | 直接调用 Standard 的 Node CLI |
| Standard 默认缓存目录不可写 | 1 | 将 `XDG_CACHE_HOME` 临时指向项目本地缓存目录 |
| 只运行 `start` 未出现桌面窗口 | 1 | 按项目结构分别启动 Vite 服务与 Electron 应用入口 |
| 用户主界面看不到品牌变化 | 1 | 增加顶部持久品牌栏和 FT 菜单标识，并清理旧开发实例后重启 |
| FiberHome 水印导致终端提示符不可见 | 1 | 回退内容层样式，仅替换背景图，并增加自动化回归测试 |
