# FiberTerm RAG MVP 实施计划

## 目标

在 `codex/rag-module-mvp` 分支以小步、可测试的方式完成 RAG-M0 与 RAG-M1：安全导入 SPN XLSX、持久化词法索引、最小管理界面及 Ask 检索与可靠引用，且不触发终端写入。

## 当前阶段

本版本功能开发已暂停，等待真实环境验证；阶段 7、8 的最后验收项保留。

## 关键问题

1. Electerm 现有的主进程、IPC 和 Ask 流程应如何承载 RAG，且不向渲染进程开放任意文件访问？
2. 哪个已维护、许可兼容的 JavaScript XLSX 库最适合真实工作簿与打包环境？

## 已做决策

| 决策 | 理由 |
|------|------|
| 实现分支从 `codex/rag-module-research` 创建 | 用户明确的、含已确认 RAG 规格的例外基线。 |
| 先创建脱敏 fixture 和测试，再实现 parser | 防止真实公司资料进入仓库或测试输出。 |

## 遇到的错误

| 错误 | 尝试次数 | 解决方案 |
|------|---------|---------|
| PowerShell 默认读取 UTF-8 附件时显示乱码 | 1 | 后续显式指定 `-Encoding UTF8`。 |
| 组合 PowerShell 搜索命令的引号不匹配 | 1 | 改为更简单的单引号正则并分步搜索。 |
| Web 查询结果按错误结构解包 | 1 | 以不依赖返回包装结构的方式重新读取结果。 |
| `npm install` 的现有 Vite/@types/node peer 解析失败 | 1 | 改用 `--legacy-peer-deps`，不升级现有依赖。 |
| `npm install --legacy-peer-deps` 网络操作超时 | 1 | ExcelJS tarball 未能可靠落盘；不再重试网络安装。 |
| 离线 npm 解析仍无 ExcelJS registry 元数据，且临时模块已被清理 | 1 | 改用锁文件已有的纯 JS `yauzl` + `sax`，避免依赖外部 registry。 |
| 预设的 unit-ci 测试文件名不存在 | 1 | 已列出真实 test 目录并读取其实际 CJS/node:test 模式。 |
| 规划记录补丁上下文不匹配 | 1 | 重新读取三个规划文件后，以当前内容为准更新。 |
| 实际 XLSX Spike 的 Node 内联脚本括号不完整 | 1 | 改用带命名 async 函数的简短内联脚本。 |
| Standard 默认尝试在用户缓存目录写入 | 1 | 显式把 `XDG_CACHE_HOME` 指向项目 `.cache` 后再运行项目内 CLI。 |
| PowerShell 把 Node 脚本正文当作自身语法 | 1 | 使用 here-string 管道明确交给 `node -` 执行。 |
| PowerShell 管道中的中文文件路径被 Node 解码为问号 | 1 | 通过 Unicode 环境变量传递路径。 |
| 真实 XLSX smoke 返回 0 个知识单元 | 1 | fixture 未覆盖的 OOXML 差异；先诊断并补充回归测试，不能进入知识模块。 |
| Parser 假定命令列为 A，真实文件从 B 开始 | 1 | 通过“命令视图”表头语义推导列偏移，并更新 fixture。 |
